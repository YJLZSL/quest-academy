# 新功能产品规格文档（PRD）

> 撰写日期：2026-08-28
> 项目：问学 Quest Academy v0.6.0
> 状态：**待确认方向** —— 本文先给出 3 个候选方案与取舍，再对推荐方案展开完整 PRD

## 零、先确认方向：3 个候选方案

「新功能」的具体方向信息不足，我基于**实际读到的项目现状**提出 3 个候选。三者的共同点是：都针对「已有代码但没产生用户价值」或「宣称有但实际没有」的缺口。

| 维度 | 方案 A：课程内容修复与扩充 | 方案 B：间隔重复复习闭环 | 方案 C：苏格拉底对话质量闭环 |
|------|---------------------------|-------------------------|---------------------------|
| **解决什么** | L0 课程因 JSON 损坏**静默消失**，新用户第一课看不到 | 学完就忘，无复习机制，留存靠不住 | 对话是核心差异化，但**没有任何质量度量** |
| **现状依据** | `l0_python_basics.json` 拼接了 2 个 JSON 对象 → `jsonDecode` 抛异常 → `CourseRepository` `catch` 后返回 `null` → 课程被跳过 | `SpacedRepetitionService`（SM-2 变体，1/3/7/14/30 天）+ `LearningEvents` 表**已实现，0 处 UI 引用** | `ConfusionDetectionService` **已实现，0 处引用**；4 个 prompt 变体已有，但无评估 |
| **用户价值** | ⭐⭐⭐⭐⭐ 直接影响新用户第一体验 | ⭐⭐⭐⭐ 长期留存的核心机制 | ⭐⭐⭐ 差异化护城河，但依赖用户量 |
| **实现成本** | 低（1 个 JSON 修复 + 内容生产，几乎无新代码） | 中（UI + 本地通知 + 调度 + 数据接入） | 高（评估体系 + 数据回流 + 埋点基建） |
| **技术风险** | 极低 | 低（算法已就绪） | 中高（需先有数据，当前无埋点） |
| **可验证性** | 强（课程是否出现，一眼可见） | 中（留存需数周才能观测） | 弱（需要用户量与人工标注） |
| **依赖前置** | 无 | 无 | 需先有活跃用户与埋点 |

### 取舍说明

- **方案 A 是"止血"而非"新功能"**，但它现在是最高优先级：一个宣称 L0–L4 的学习应用，实际只加载得出 L1，且这个失败**完全静默**（无崩溃、无日志、无报错）。任何新功能都建立在这个地基上。
- **方案 B 是"把已建好的东西用起来"**。算法、数据表、服务都已写完，只差接进 UI 和调度。投入产出比最高，且直接命中 AI 自学类产品的核心命题（学完不忘）。
- **方案 C 最有长期价值但现在做不了**。没有用户量、没有埋点、没有对话数据，评估体系建起来也是空的。**建议列为 P2，等 A、B 落地并有真实用户后再启动。**

### 我的建议

**先 A 后 B，C 暂缓**：A 作为 v0.6.1 热修（1 天内），B 作为 v0.7.0 主线。两者共享一个前提——先把安卓构建跑通，否则改完无法验证。

## 一、背景与目标

### 1.1 背景

问学 Quest Academy 定位为「引导式 AI 学习应用」，以苏格拉底式提问为核心，提供 L0–L4 五级学习路径。当前 v0.6.0 完成品牌升级，代码规模约 31,000 行（119 个 Dart 文件），481 个测试用例，Android + Windows 双端。

但实地核查发现**产品宣传与实际交付之间存在明显缺口**：

| 宣称 | 实际 |
|------|------|
| L0–L4 五级学习路径 | 仅 L0、L1 两门课程文件；且 L0 因 JSON 损坏**加载不出来** |
| 间隔重复复习 | 算法与数据表已实现，**未接入任何界面** |
| 困惑检测自动降级 | 服务已实现，**0 处引用** |
| 学习者画像 | `LearnerProfiles` 表已建，**0 处使用** |
| 149+ 测试用例 | 36 个测试失败，CI 中已设 `continue-on-error` 永久跳过 |

同时，**安卓端构建当前完全跑不通**（详见《诊断-安卓构建卡死.md》），导致任何改动都无法在真机验证。

### 1.2 目标

本 PRD 覆盖推荐方案 **A（课程内容修复与扩充）+ B（间隔重复复习闭环）**。

**业务目标**

1. **止血**：让 L0 课程恢复可见，消除静默失败，建立课程数据校验机制防止复发
2. **补齐**：把学习路径从"2 门课（其中 1 门坏）"推进到"L0–L2 完整可用"
3. **闭环**：把已实现的间隔重复算法接进产品，让"学完"变成"学会"

**非目标（本次不做）**

- 不做苏格拉底对话质量评估体系（方案 C，依赖用户量）
- 不做学习者画像与个性化推荐（依赖数据积累）
- 不做 iOS / macOS / Linux 平台（AGENTS.md 明确限定 Android + Windows）
- 不做 UI 视觉重构（v0.6.0 刚完成品牌重设计）

### 1.3 成功指标（North Star）

| 指标 | 定义 | 当前 | 目标 |
|------|------|------|------|
| 课程加载成功率 | 启动时成功解析的课程数 / 课程文件数 | 50%（1/2） | **100%** |
| 7 日留存 | 安装后第 7 天仍活跃的用户占比 | 无埋点，未知 | 建立基线，≥ 20% |
| 知识点复习完成率 | 到期复习项中被完成的占比 | 无此功能 | ≥ 40% |
| 次周回访率 | 完成首次学习后次周回访占比 | 无埋点，未知 | 建立基线 |

> 说明：当前**没有任何埋点**，留存类指标无法观测。本 PRD 将「最小埋点」纳入 MVP 范围，否则上述目标无法验证。

## 二、目标用户与使用场景

### 2.1 目标用户

| 用户类型 | 特征 | 核心诉求 | 优先级 |
|----------|------|----------|--------|
| **AI 自学入门者** | 零基础或转行，想系统学 AI/编程，缺乏路径 | 有清晰路径、有人引导、能坚持 | P0 |
| **在职提升者** | 有编程基础，碎片时间学习，容易中断 | 复习提醒、进度可视化、低启动成本 | P0 |
| **自学者（学生）** | 有整块时间，配合课程学习 | 体系化内容、练习与反馈 | P1 |

### 2.2 核心使用场景

**场景 1：新用户第一次打开（对应方案 A）**

```
下载安装 → 引导页 → 配置 API Key → 首页 → 点击「学习路径」
期望：看到 L0「Python 基础」4 个模块
现状：只能看到 L1，L0 凭空消失，用户以为「就这些内容」
```

这个场景的失败是**致命且不可见**的——用户不会报错，只会觉得内容太少然后离开。

**场景 2：学完一周后回来（对应方案 B）**

```
上周学完 L0 第 1 章 → 本周打开应用
期望：首页提示「有 5 个知识点到了复习时间」→ 一键进入复习
现状：无提醒、无复习入口，学过的知识点石沉大海
```

**场景 3：碎片时间复习（对应方案 B）**

```
通勤路上 → 收到复习提醒通知 → 点击进入 → 3 分钟完成一轮复习 → Streak 延续
```

## 四、关键交互与业务流程

### 4.1 课程加载与容错流程（方案 A）

```
应用启动
   │
   ├─► AssetManifest 扫描 assets/courses/*.json
   │
   ├─► 逐个 jsonDecode
   │      │
   │      ├─ 成功 ─► Course.fromJson ─► 加入课程列表
   │      │
   │      └─ 失败 ─► 【现状】catch → return null → 静默跳过
   │                 【目标】catch → 记录错误到 _loadErrors
   │                        └─► 启动完成后
   │                               ├─ 有失败 ─► 设置页显示红色告警条
   │                               │            「N 门课程加载失败，点击查看」
   │                               └─ 无失败 ─► 正常
   │
   └─► 学习路径页渲染
```

**关键改动点**（`lib/data/repositories/course_repository.dart`）：

```dart
// 现状
} catch (_) {
  return null;
}

// 目标
} catch (e, st) {
  _loadErrors.add(CourseLoadError(path: path, error: e, stackTrace: st));
  return null;
}
```

并新增 `List<CourseLoadError> get loadErrors` 供 UI 读取。

### 4.2 间隔重复复习流程（方案 B）

```
知识点完成
   │
   ├─► 写入 Progress（status=completed, completedAt）
   ├─► 写入 LearningEvents（type=completed）
   └─► SpacedRepetitionService 计算下次复习时间
        间隔序列：1 天 → 3 天 → 7 天 → 14 天 → 30 天
   │
   ▼
每日应用启动
   │
   ├─► SpacedRepetitionService.getReviewReminders()
   │      计算 urgency = f(daysSinceLastStudy, 复习次数)
   │
   ├─► 有到期项？
   │      │
   │      ├─ 是 ─► 首页「今日复习」卡片显示 N 项
   │      │         └─► 点击 ─► 复习页（按 urgency 降序）
   │      │                     └─► 知识点复习
   │      │                           ├─ 轻测验（3 题）或
   │      │                           └─ 苏格拉底追问（1 轮）
   │      │                           └─► 完成 ─► 更新下次复习时间
   │      │                                    └─► +XP / 粒子庆祝
   │      │
   │      └─ 否 ─► 卡片显示「暂无复习任务」+ 下次复习日期
   │
   └─► 本地通知（若开启）
         每日 <用户设定时间> 检查，有到期项则推送
```

### 4.3 复习紧迫度计算

沿用 `SpacedRepetitionService` 已有的 `ReviewReminder.urgency`（0.0–1.0）。UI 侧映射：

| urgency | 展示 | 排序权重 |
|---------|------|----------|
| ≥ 0.8 | 红色「已逾期」 | 3 |
| 0.5–0.8 | 橙色「今日复习」 | 2 |
| < 0.5 | 灰色「即将到期」 | 1 |

## 五、非功能性要求

### 5.1 性能

| 项 | 要求 | 测量方式 |
|----|------|----------|
| 课程加载 | 冷启动解析全部课程 ≤ 200ms | 现有 `_cache` 机制 + 埋点计时 |
| 复习列表渲染 | 100 个复习项滚动保持 60fps | `PerformanceOverlay` 无红条（沿用 v0.3.0 标准） |
| 首页增量渲染 | 「今日复习」卡片不得阻塞首屏，异步加载 | 首屏 ≤ 500ms |
| 复习调度计算 | 1000 条 LearningEvents 下 ≤ 100ms | 单元测试计时断言 |

### 5.2 兼容性

| 项 | 要求 |
|----|------|
| 平台 | Android（minSdk 24+）+ Windows 10+，**不含 iOS/macOS/Linux** |
| 屏幕 | 移动 < 600 / 平板 600–1023 / 桌面 ≥ 1024 三档断点（沿用 `docs/page-wireframes` 约定） |
| 无障碍 | 复习卡片需 `Semantics` 标注；`reduceMotion` 开启时粒子庆祝降级为即时切换 |
| 主题 | 三档主题风味（standard / minimal / minecraft）均需正常渲染新组件 |
| 数据迁移 | `schemaVersion` 升级需提供迁移脚本，禁止破坏性变更 |

### 5.3 稳定性

| 项 | 要求 |
|----|------|
| 容错 | 单个课程文件损坏**不得**导致应用崩溃或其他课程不可用（现状已满足，需保留） |
| 可观测 | 任何课程加载失败必须在 UI 可见（修复现状的静默失败） |
| 通知可靠性 | 通知权限被拒时静默降级为应用内提醒，不得反复弹窗 |
| 降级 | `SpacedRepetitionService` 计算异常时回退到「全部待复习」列表，不得白屏 |
| 数据安全 | 埋点数据仅本地存储，复用现有 `secure_storage_service` 加密策略，**永不上传** |

### 5.4 安全红线（沿用 AGENTS.md）

- API Key 仅本地加密存储，日志自动脱敏（`secure_log_interceptor.dart` 已实现）
- 埋点数据不得包含对话内容、API Key、笔记正文
- 数据导出需用户主动触发并明确告知范围
