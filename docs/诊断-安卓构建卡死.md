### 2.6 L6 — Kotlin 跨盘符崩溃（最隐蔽的一个）

现象：Kotlin 编译插件源码时报错，表面看是缓存问题：

```
Execution failed for task ':package_info_plus:compileDebugKotlin'.
> java.lang.Exception: Could not close incremental caches in
  D:\AIKFCC\AI  Classroom\build\package_info_plus\kotlin\...:
  class-fq-name-to-source.tab, source-to-classes.tab, internal-name-to-source.tab
```

清理缓存无效。抓取 `Suppressed` 异常才看到真正原因：

```
Suppressed: java.lang.IllegalArgumentException:
  this and base files have different roots:
  C:\Users\23501\AppData\Local\Pub\Cache\hosted\pub.dev\package_info_plus-8.3.1\android\src\main\kotlin\...
  and
  D:\AIKFCC\AI  Classroom\android.
```

**根因**：项目在 `D:`，而 Pub 缓存默认在 `C:\Users\<user>\AppData\Local\Pub\Cache`。
Kotlin 增量编译器要对源码路径做 `Path.relativize()`，Java 在**跨盘符时直接抛异常**。

**修复**：把 Pub 缓存迁到与项目同盘：

```bash
# 1. 复制缓存（855MB，42,268 个文件，约 46 秒）
xcopy /E /I /Q "%LOCALAPPDATA%\Pub\Cache" "D:\PubCache"

# 2. 设置环境变量（建议设为系统级永久变量）
setx PUB_CACHE "D:\PubCache"

# 3. 重新解析依赖，使 .dart_tool/package_config.json 指向新路径
flutter pub get
```

验证：`package_config.json` 中所有包路径应变为 `file:///D:/PubCache/...`。

### 2.7 L7 — 插件 compileSdk 版本过低

```
Dependency 'androidx.window.extensions.core:core:1.0.0' requires libraries and applications that
depend on it to compile against version 33 or later of the Android APIs.

:flutter_native_splash is currently compiled against android-31.
```

**修复**：在 `android/build.gradle.kts` 统一子模块 compileSdk。**注意顺序**——必须放在
`subprojects { project.evaluationDependsOn(":app") }` **之前**，否则子项目已被求值，
`afterEvaluate` 会抛 `Cannot run Project.afterEvaluate(Action) when the project is already evaluated`。

```kotlin
subprojects {
    afterEvaluate {
        val androidExt = project.extensions.findByName("android")
        if (androidExt is com.android.build.gradle.BaseExtension) {
            androidExt.compileSdkVersion(36)
        }
    }
}
subprojects {
    project.evaluationDependsOn(":app")
}
```

## 五、附带发现（非构建问题，但建议尽快处理）

### 5.1 P0：`l0_python_basics.json` 课程数据损坏

`assets/courses/l0_python_basics.json` 文件（共 1117 行）里**拼接了两个完整 JSON 对象**：

```
第 1 个对象（第 1–883 行）：modules: 4 项    ← 完整版本，应保留
第 2 个对象（第 884–1117 行）：modules: 1 项 ← 重复且残缺的旧版本，应删除
```

第 883 行是第一个对象的收尾 `}`，第 884 行是第二个对象的起始 `{`。

`jsonDecode()` 会抛 `FormatException: Extra data`。

而 `CourseRepository._loadCourseFile` 是这样处理的：

```dart
try {
  final decoded = jsonDecode(raw);
  ...
} catch (_) {
  // 资产缺失或 JSON 损坏时返回 null，调用方将跳过该课程。
  return null;
}
```

**后果**：L0「Python 基础」课程被**静默跳过** —— 应用不崩溃、不报错，但**入门课程在 App 里完全看不见**，用户只能看到 L1。

这是最危险的一类 Bug：静默失败 + 影响的是新用户的第一课。

**修复**：删除第 884–1117 行（第二个 JSON 对象），只保留第 1–883 行那个 `modules: 4 项` 的完整版本。

**建议同时做**：把 `catch (_) { return null; }` 改成至少打一条日志，避免同类问题再次静默。
